# Сбор публичных профилей и конкурентный анализ

## Цель

Сайт принимает публичную ссылку Kwork, FL.ru или Freelance.ru, собирает доступные данные профиля на сервере, строит отчёт по ним и сравнивает основной профиль с 1–3 публичными профилями конкурентов.

## Границы

- Поддерживаются только публичные HTTP(S)-профили трёх площадок: Kwork, FL.ru и Freelance.ru.
- Нет авторизации, обхода CAPTCHA, прокси, платных scraper API или обхода ограничений площадок.
- Если страница не загрузилась, закрыта, изменила структуру или содержит мало данных, UI объясняет причину и предлагает ручной ввод; данные не выдумываются.
- Один пользовательский запуск создаёт не более одного AI-запроса. Сбор основного профиля и профилей конкурентов выполняется до AI-запроса.

## Архитектура

`POST /api/analyze` получает основной профиль и ссылки конкурентов. Серверный модуль `profile-fetcher` проверяет URL, определяет площадку, загружает публичный HTML с лимитом времени и размера и передаёт его адаптеру площадки. Адаптеры возвращают единый `ProfileInput` и список предупреждений о неполных полях.

Локальный scoring работает по собранному профилю всегда. Для конкурентного режима отдельный `competitive-analysis` сравнивает основной профиль с каждым конкурентом по одинаковым сигналам: позиционирование, конкретика оффера, доказательства, отзывы/заказы, портфолио и прозрачность цены. Результат добавляется к отчёту в отдельный блок. AI при наличии доступа получает только нормализованные данные и сравнительные выводы, а не HTML.

## Модель данных

- `PlatformId`: `kwork | flru | freelanceRu`.
- `CollectedProfile`: `profile`, `platform`, `sourceUrl`, `warnings`, `collectedFields`.
- `CompetitorComparison`: имя, платформа, сильные стороны, преимущество пользователя, отставания пользователя, действия.
- В `ProfileAudit` добавляется `source` с состоянием сбора и `competitive` с итогом сравнения, только для конкурентного режима.

## UX

1. Поле основной ссылки принимает все три площадки и показывает определённую площадку после проверки.
2. В конкурентном режиме каждая строка принимает ссылку конкурента; старые ручные поля остаются как fallback.
3. Loading state показывает этапы: «Собираем профиль», «Сравниваем конкурентов», «Готовим отчёт».
4. Отчёт показывает бейдж платформы и блок «Данные собраны из публичного профиля» либо предупреждение о ручном/fallback-вводе.
5. Конкурентный раздел содержит: таблицу сигналов, сильные стороны конкурентов, точки преимущества пользователя и конкретные правки профиля.

## Ошибки и защита

- Разрешаются только HTTPS/HTTP URL и точные домены/поддомены поддерживаемых площадок; блокируются localhost, IP-адреса и внутренние адреса.
- Таймаут загрузки 8 секунд, максимальный размер HTML 1 МБ, максимум три конкурента.
- Все поля нормализуются и ограничиваются существующими лимитами перед scoring и AI.
- Ответ сервера всегда содержит рабочий локальный отчёт, если хотя бы есть ручные данные; иначе возвращает понятную валидационную ошибку.

## Проверка

- Тесты URL-валидации и определения площадки.
- Тесты HTML-адаптеров на сохранённых HTML fixtures каждой биржи.
- Тесты конкурентного сравнения с предсказуемыми входными профилями.
- Тест endpoint: сбор успешен, частичный сбор, ошибка площадки, конкурентный режим.
- Полный `npm test -- --run`, `npm run lint`, `npm run build`.

## Решение

Начальная реализация использует обычную серверную загрузку публичного HTML. Headless-браузер не включается в MVP: его можно добавить позднее как отдельный fallback, если конкретная площадка действительно отдаёт профиль только через JavaScript.
